# 代码、安全设计与本地生产候选验收复审

日期：2026-10-14。范围：Authova Core、Contracts、Console；Apache-2.0；App 独立身份域。继续排除组织、业务 RBAC/PDP 和占位扩展。全部工作在本地，未 push、未运行远端 CI、未发布。

## 本轮修复

| 风险/缺陷 | 修复与验证边界 |
| --- | --- |
| 取消授权流程被视为完成，仍能创建授权码 | `complete` 状态、authorize purpose、User/Session 必须同时满足。修复前确实取得 code，但交换返回 503；没有证据证明曾取得有效登录令牌。两库反例固定 |
| 密码等凭据变更后，已验证但未完成的流程继续使用旧证明 | Flow 持久化 AuthEpoch；MFA、恢复、consent 和完成动作检查当前 User epoch/status。旧二进制留下的零 epoch 待完成流程拒绝，需要重新登录 |
| MFA 策略变更发生在 consent 之前 | 完成授权再次检查 App/Client/User 当前 MFA 要求；Session 身份、到期、epoch 和 family 关联进一步校验 |
| 旧 OTP challenge 可替代当前 challenge | challenge 必须与 Flow 当前指针一致；验证码单次消费和错误计数仍在同一事务 |
| 地址确认改变了最近主认证时间 | 确认标识保留原主认证时间；绑定和 federation link 重新检查有效 session/epoch/最近认证 |
| 上游 email 的 verified 位与另一来源的邮箱混用 | 邮箱和 verified 位从同一来源成对使用，UserInfo subject 必须与 ID token subject 一致，允许无 UserInfo 的合法提供方 |
| 外部 HTTP 资源不受控 | 共用受限 transport；DNS 在每次拨号检查 public IP、不使用环境 proxy、不跟随 redirect、响应体最多 4 MiB、TLS 最低 1.2、总时限和连接闲置回收 |
| 重试 OAuth 鉴权方式可能重放 refresh | 根据 metadata 明确 token auth style；Console public Client 固定参数方式，禁止自动探测重放 |
| BFF 并发 refresh/退出竞态 | 共享锁、网络调用前持久化 pending、未知结果要求重新认证、SET XX 防止刷新复活已删除会话；真实 Valkey 竞争/故障用例 |
| 依赖错误被伪装为未授权或 inactive | 平台会话、App 管理、发现、连接、refresh 和撤销路径保留 503；真实 test-owned TCP 代理断链与恢复，两库验证 |
| KDF 资源耗尽与取消 | 有界并发和队列（并发预算的 4 倍）、过载 503、取消后不再开始昂贵计算；规范化 identifier 的限流 key |
| DB 池有界但 HTTP 等待请求无界 | Core 1024/BFF 256 并发 admission，上限过载 503、liveness 保持可用；真实 HTTP 阻塞依赖、拒绝和恢复测试 |
| 无鉴权请求先生成 RSA 密钥 | 先认证/授权，生成后再核验；每 App 每分钟 5 次轮换限制 |
| 启动时只确认 RLS 策略名称 | 检查 18 张 App 表 FORCE RLS、唯一 app_scope、实际 USING/WITH CHECK 表达式及角色；拒绝 PG shadow search_path、role membership/schema CREATE/table owner/特权。MySQL 仅允许作用域 DML/USAGE，不允许全局 DML、动态特权、角色或 grant option |
| 迁移被改写仍可启动 | runtime 检查两版本历史 checksum；真实 v1→v2 回填、dirty/checksum 拒绝和权限反例 |
| 清理记录不完整/计数可能包含回滚 | 分批清理临时链、审计、outbox、管理会话和平台幂等记录；锁定后删除、按提交计数；两库注入中途触发器错误证明全回滚 |
| worker 旧结果覆盖新租约/过期消息/发送取消 | attempt fencing；新 OTP 到期时间 5 分钟；4 个发送 worker、有限 DB/提供方时限；SMTP ctx 取消关闭连接；取消后停止新发送。真实队列 fencing、并发/到期和停滞 SMTP 测试 |
| listener 关闭后 CLI 提前退出 | Core/Console 等待 HTTP drain 完成，10 秒后强制关闭。真实进行中 HTTP 请求测试 |
| metrics 隐藏 5xx、故障日志洪泛 | 记录实际状态类别、5xx/panic、inflight/时长、Go heap/GC/goroutine、DB pool/wait；重复协议故障日志每秒最多一次，审计不采样 |
| Console 静态资产边界 | os.OpenRoot 限定公共文件系统；遍历与向目录外的 symlink 均不得泄漏文件，真实文件系统测试。部署资产目录仍仅放公共文件 |
| Console 对未知写入/依赖故障/登出处理不正确 | App/Client 创建稳定幂等 key，payload 冻结及 10 分钟窗口；未知 operator/connection 写入不盲重试；bootstrap 503 可恢复；失败登出保留登录；响应体中断/异常 JSON 仍为 unknown，登出只接受契约 204 或明确 401 |
| 内省热路径大量解密/解析 | 单主库状态投影 + 已验签的不可变 claims；同一请求复用 JWT 解析，单测覆盖签名篡改/typ/issuer/缺失声明/过期及不完整协议响应，仍每次 RSA 验签；Client 仅缓存“当前密文对应的解析结果”，每次重新查主库密文/status/权限。权限/secret 变更回归，禁止缓存 positive active |
| 压测生成器自身内存随时间增长 | 有界直方图、显式 >120s 溢出、每分钟进度/生成器资源；统计全部计划、失败、丢队列和 drain 延迟，不能用完成数掩盖过载 |

| 检查面 | 已有机制与本轮本地证据 | 仍需部署验证 |

| 登录和账户接管 | OTP/TOTP 单次与限流、最近主认证、AuthEpoch、绑定来源、密码变更撤销 | 真实短信/Email 可达与提供方风险、用户恢复运营流程 |
| OAuth/OIDC | Code/S256、nonce/issuer/audience/at_hash、RS256、明确 auth style、一次 code/refresh、reuse revoke | 各真实 IdP 兼容和独立协议认证 |
| 管理权限 | 平台与 App 管理身份分离、当前固定角色/最后 owner、写入最近 MFA | 运维管理员的最小权限和私密安全响应联系人 |

## 实际验收

原始报告保存在 `evidence/review-2026-10-14/`，索引 `manifest.json` 记录 SHA-256。`STATUS.md` 与 `PERFORMANCE.md` 给出最终结论，失败轮次不删除。

- `make verify`：实际 PG/MySQL、Go vet/race、Contracts lint/生成编译、Console 类型/lint/108 行为测试、维护负面 gate、真实 Chrome 双 App/SMTP/PKCE/refresh/UserInfo/自助账户。
- 真实 Valkey：并发 refresh 单次外部调用、失败不重放、logout 不复活、故障 503、CSRF 拒绝。
- 网络：测试自己的 TCP 代理切断 DB 流量，未关闭别的项目数据库。依赖失败和恢复明确可观察。
- 双副本：共用真实 DB 的两个独立 Core provider，code 一次消费、refresh 一次旋转和 reuse revoke 跨副本可见。这不是跨主机 HA 演练。
- 真实 HTTPS：测试证书链验证开启，production Cookie Secure/HttpOnly、CSRF、Code/PKCE 和内省；没有关闭 TLS 校验。
- 正常 TTL 协议持续 30 分钟：每库 7 次实际 HTTP refresh、持续有效内省；PG 16025、MySQL 16228 次检查。PG 的组合命令后续 MySQL 启动失败，整体记为失败；MySQL 单独通过的证据另列。数据库夹具创建初始身份，不计为生产密码登录负载。
- 全量恢复：两库各 1200 万 COUNT、各 1000 个解密 User 精确比对和 RSA 私钥解析；MySQL 限制 INSERT 提交批次后完成。详见恢复报告，不能推导跨机 HA/RPO。
- 静态/安全：采用兼容 Go 1.27.2 的静态工具，保留旧 staticcheck 不兼容 export data 的失败记录；govulncheck 可达/导入包为 0，4 项未调用模块发现保留；生产 npm audit 为 0。
- SAST：原 gosec 分析库无法读取 Go 1.27；保留失败报告。本地兼容构建（gosec v2.29.0 + x/tools v0.51.0，未改产品依赖）完成扫描，Core 50/BFF 10 项原始告警逐项记录 rationale，未标成零告警；临时工具也不等于独立外部审查。静态资源越界、负 TOTP 计数、异常协议响应与迁移解锁超时已补强。详见 `review-sast-triage.json`。
- OCI：最终源码的非 root/只读根文件系统/去除 capability 启动与鉴权 gate，具体镜像 digest 和结果在证据索引。

## 已知的边界

1. 容量门槛以整段成功 QPS、错误、丢队列、延迟同时判断；小时测量没有达到目标时必须记为失败，不能以历史 120 秒成功替代。
2. Console 创建意图的幂等 key 仅保存在当前页面内存。完整刷新/离开页面后若结果未知，必须先核对服务端记录；未实现跨设备自动恢复。
3. SMTP 受理不是送达证明，也没有 exactly-once 保证；租约网络未知可重复投递，验证码消费仍一次。
4. 单机源库与新库的完整恢复、两个本地 provider 和测试 TLS，分别不能证明生产灾备、多机故障转移及客户 ingress 已验收。
5. 本轮是开发者本地复审与自动化证据，没有独立外部渗透审查。远端 CI 和公开发布均未执行。
